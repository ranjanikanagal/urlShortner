# AI Usage Log
. The AI wrote the code," it's the review step on top of it.

| Area | AI's first draft | Human review finding | Resolution |
|---|---|---|---|
| Scaffold & boilerplate | `pom.xml`, DTOs, `GlobalExceptionHandler`, Dockerfile, docker-compose, Flyway migrations | Low risk — mechanical code a compile + test suite mostly self-checks | Accepted with checks on dependency scopes, no stack-trace leaks, multi-stage Docker build |
| Short code generation | Sequential auto-increment ID encoded as Base62 | Leaks how many URLs exist and lets anyone enumerate other users' links; sequence becomes a write hotspot under concurrent creates | Rejected — switched to random generation with a bounded (5-attempt) collision retry against a DB uniqueness check |
| Cache strategy | Cache populated on write only | A cold instance with no local cache history would 404 on resolve instead of falling back to Postgres | Changed to real cache-aside: resolve always falls back to the DB on a miss and repopulates Redis |
| Duplicate URL detection scope | Deduplicated *all* create requests, including ones with a custom alias | A caller asking for `myalias` could silently get back a different, previously-generated code instead | Narrowed to only short-circuit generated-code requests; a custom alias always creates its own row |
| Retry logic placement | `@Retryable` on private methods inside `UrlShortenerServiceImpl` | Doesn't work — Spring's retry AOP proxy only intercepts calls from outside the bean; private self-invocation bypasses it silently | Extracted a separate `RedisCacheClient` bean so retry-annotated methods are called through the proxy |
| Async analytics failure mode | No explicit handling for a DB write failing after the redirect already returned | There's no caller left to propagate an exception to at that point | Log and swallow inside `AnalyticsServiceImpl.recordClickAsync` — a lost analytics event is acceptable, an already-sent redirect can't be un-sent |
| Rate limiter path scoping | Interceptor pattern `/{shortCode}` | Also matched `/swagger-ui.html`, `/actuator/health`, and the OpenAPI JSON — routine docs/health traffic consumed the same quota as real redirects | Fixed with explicit `excludePathPatterns` |
| GeoIP resolution | Invented plausible-looking country codes from IP address ranges as a "good enough" heuristic | Fabricating data that looks real is worse than clearly returning "Unknown" | Replaced with `StubGeoLookupService` — reads a header a real edge/CDN layer would set, documented as a stub in code and `docs/LIMITATIONS.md` |
| Test coverage | Happy-path tests only, for every endpoint including new ones | Happy path alone doesn't exercise the actual point of a feature | Added cache-miss-falls-back-to-DB, expired-link, alias-conflict, duplicate-URL short-circuit, update-changes-both-fields, delete-cleans-both-DB-and-cache, redirect-does-not-record-a-click-on-404 |
| Exception handling breadth | `@ExceptionHandler(Exception.class)` as the only catch-all | Caught framework-level exceptions Spring already handles correctly (e.g. `NoResourceFoundException` for an unmatched route), turning a normal 404 into a misleading 500; separately, the catch-all logged nothing, making real 500s undebuggable | Added a specific `NoResourceFoundException` handler returning a proper 404; added `log.error(...)` to the generic handler and `log.warn(...)` to the domain-specific ones |
